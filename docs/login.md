# Login verification


Saving a password does not verify it. Login pages remain open with live status: saved, testing, additional verification required, verified, or failed. The agent tests credentials in the site browser and calls `vault_login_feedback` with visible evidence from the bound site. MFA is not success. Failed credentials can be corrected through a fresh one-time form; `vault_wait` follows the replacement request. No password or arbitrary page text appears in feedback. Status links last 30 minutes and stop updating if the daemon restarts; reopen feedback with `show_page` to create a new link. Verification describes the observed session, not permanent credential validity.

Login verification is a continuous agent workflow: `vault_request` → `vault_wait` → attempt the site login immediately. For 2FA, `vault_login_challenge` updates the existing page with a code field or app-approval instruction. `vault_challenge_wait` returns only readiness; `vault_challenge_fill` passes the short-lived, single-use code through the secret-fill path, bound to the browser session and exact site origin. The code never appears in MCP results, audit records, or persistent vault storage. The agent checks the site’s response, replaces rejected/expired challenges when appropriate, and reports verified only after observing an authenticated session. The UI depends on the active agent continuing the workflow; saving alone does not run an independent background agent. Login challenges do not replace purchase or bank authorization.
